概述

RAG（Retrieval-Augmented Generation，检索增强生成）是解决大模型"知识过时"和"幻觉"问题的核心技术。它通过在生成回答前先检索外部知识库，将相关上下文注入Prompt，使大模型的回答基于真实数据，而非仅依赖训练时的记忆。

本章将系统讲解RAG的技术原理、架构演进、关键组件，以及从Naive RAG到Agentic RAG的技术发展脉络。

一、为什么需要RAG

1.1 大模型的三大局限

局限表现RAG如何解决
知识过时训练数据截止后的事件无法回答实时检索最新数据
幻觉问题编造不存在的事实基于检索到的真实文档回答
领域缺失专业领域知识不足接入领域知识库

1.2 RAG vs 微调 vs 预训练

维度RAG微调预训练
知识更新实时需重新训练需重新训练
成本低中极高
适用场景知识密集型问答风格/格式适配基础能力提升
可解释性高（可溯源）低低
数据安全可控（本地知识库）需上传数据需上传数据

结论：在大多数企业场景中，RAG是性价比最高的方案。

二、RAG核心架构

2.1 基本流程

用户提问 → Query编码 → 向量检索 → 上下文组装 → LLM生成 → 返回答案

RAG的核心是"先检索，后生成"，将检索到的相关文档片段作为上下文，与用户问题一起输入LLM。

2.2 Naive RAG架构

最基础的RAG实现，包含三个阶段：

  1. 索引阶段：文档分块 → Embedding → 存入向量数据库
  2. 检索阶段：Query Embedding → 向量相似度搜索 → Top-K文档
  3. 生成阶段：Prompt组装（Query + 检索结果）→ LLM生成回答
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│  索引阶段    │     │  检索阶段     │     │  生成阶段     │
│             │     │              │     │              │
│ 文档 → 分块  │────→│ Query → 向量  │────→│ Prompt组装   │
│ → Embedding │     │ → Top-K检索   │     │ → LLM生成    │
│ → 向量库    │     │              │     │              │
└─────────────┘     └──────────────┘     └──────────────┘

2.3 Naive RAG的不足

  • 检索质量低：单一向量检索可能返回不相关文档
  • 分块不合理：固定长度分块会截断语义完整性
  • 缺乏推理：无法判断检索结果是否真正回答了问题
  • 上下文冗余：Top-K文档可能包含大量无关信息

三、RAG技术演进

Advanced RAG在Naive RAG基础上，对检索前、检索中、检索后三个环节进行优化。

检索中优化（Retrieval）

混合检索（Hybrid Search）结合向量检索和关键词检索的优势：

 5def hybrid_search(
 6    query: str,
 7    query_embedding: list[float],
 8    vector_store,
 9    bm25_scores: list[tuple[str, float]],
10    alpha: float = 0.7,
11    top_k: int = 5
12) -> list[tuple[str, float]]:
13    vector_results = vector_store.search(query_embedding, top_k=top_k * 2)
14    vector_dict = {doc: score for doc, score in vector_results}
15    bm25_dict = {doc: score for doc, score in bm25_scores}
16
17    all_docs = set(vector_dict.keys()) | set(bm25_dict.keys())
18
19    max_vec = max(vector_dict.values()) if vector_dict else 1.0
20    max_bm25 = max(bm25_dict.values()) if bm25_dict else 1.0
21
22    combined = []
23    for doc in all_docs:
24        vec_score = vector_dict.get(doc, 0.0) / max_vec
25        bm25_score = bm25_dict.get(doc, 0.0) / max_bm25
26        final_score = alpha * vec_score + (1 - alpha) * bm25_score
27        combined.append((doc, final_score))
28
29    combined.sort(key=lambda x: x[1], reverse=True)
30    return combined[:top_k]

3.2 Modular RAG

Modular RAG将RAG系统拆分为可插拔的模块，每个模块可独立优化和替换。

模块功能可选方案
索引文档处理与存储FAISS, Milvus, Elasticsearch
检索语义/关键词/混合向量检索, BM25, 混合检索

3.3 GraphRAG

GraphRAG是微软提出的一种结合知识图谱的RAG架构，解决了传统RAG在全局性问题上的不足。

核心思想

传统RAG擅长局部细节问答，但面对"总结所有文档的核心观点"这类全局性问题时表现不佳。GraphRAG通过构建文档的知识图谱，实现全局-局部双层搜索。

工作流程

1. 文档分块 → 实体抽取 → 关系抽取 → 构建知识图谱
2. 社区检测 → 生成社区摘要 → 建立层次化索引
3. 查询时：局部查询走向量检索，全局查询走社区摘要

32        self.relations: list[Relation] = []

35    def extract_entities_and_relations(self, text: str) -> tuple[list[Entity], list[Relation]]:

47        return self._parse_extraction(response)
48
49    def build_communities(self) -> list[Community]:
50        entity_names = [e.name for e in self.entities]
51        adjacency = {name: set() for name in entity_names}
52        for r in self.relations:
53            if r.source in adjacency:
54                adjacency[r.source].add(r.target)
55            if r.target in adjacency:
56                adjacency[r.target].add(r.source)
57
58        visited = set()
59        communities = []
60        community_id = 0
61
62        for entity in entity_names:
63            if entity not in visited:
64                community_entities = self._bfs(entity, adjacency, visited)
65                community = Community(
66                    id=f"community_{community_id}",
67                    entities=community_entities,
68                    summary="",
69                    level=0
70                )
71                communities.append(community)
72                community_id += 1
73
74        self.communities = communities
75        return communities
76
77    def _bfs(self, start: str, adjacency: dict, visited: set) -> list[str]:
78        queue = [start]
79        component = []
80        while queue:
81            node = queue.pop(0)
82            if node not in visited:
83                visited.add(node)
84                component.append(node)
85                for neighbor in adjacency.get(node, set()):
86                    if neighbor not in visited:
87                        queue.append(neighbor)
88        return component
89
90    def _parse_extraction(self, response: str) -> tuple[list[Entity], list[Relation]]:
91        import json
92        try:
93            data = json.loads(response)
94            entities = [Entity(**e) for e in data.get("entities", [])]
95            relations = [Relation(**r) for r in data.get("relations", [])]
96            return entities, relations
97        except json.JSONDecodeError:
98            return [], []

3.4 Agentic RAG

Agentic RAG是RAG技术的最新演进，将Agent的自主决策能力引入RAG流程。

核心特征

  • 自适应检索：Agent根据问题类型自主决定是否检索、检索什么、检索几次
  • 工具调用：Agent可调用多种工具（搜索引擎、数据库、API等）
  • 反思迭代：Agent可评估检索结果质量，决定是否重新检索
  • 多步推理：复杂问题可拆解为多步，每步独立检索和推理

 2from typing import Optional
 3
 4
 5class AgentAction(Enum):
 6    RETRIEVE = "retrieve"
 7    GENERATE = "generate"
 8    REFINE_QUERY = "refine_query"
 9    STOP = "stop"

12class AgenticRAG:
13    def __init__(self, llm_client, vector_store, max_iterations: int = 5):

15        self.vector_store = vector_store
16        self.max_iterations = max_iterations
17
18    def decide_action(self, query: str, context: str, iteration: int) -> AgentAction:
19        if iteration >= self.max_iterations:
20            return AgentAction.GENERATE
21
22        prompt = f"""基于当前状态，决定下一步操作：
23
24用户问题：{query}
25当前上下文：{context[:500]}
26迭代次数：{iteration}
27
28可选操作：
29- RETRIEVE: 需要更多信息，执行检索
30- GENERATE: 信息充分，生成回答
31- REFINE_QUERY: 当前查询不够精确，需要改写
32- STOP: 无法回答，停止
33
34请只输出操作名称："""
35
36        response = self.llm_client.call(prompt).strip().upper()
37        try:
38            return AgentAction[response]
39        except KeyError:
40            return AgentAction.GENERATE
41
42    def run(self, query: str) -> str:
43        context = ""
44        current_query = query
45
46        for iteration in range(self.max_iterations):
47            action = self.decide_action(query, context, iteration)
48
49            if action == AgentAction.RETRIEVE:
50                query_emb = self._get_embedding(current_query)
51                results = self.vector_store.search(query_emb, top_k=3)
52                new_context = "\n".join([doc for doc, _ in results])
53                context += f"\n--- 检索结果 {iteration + 1} ---\n{new_context}"
54
55            elif action == AgentAction.REFINE_QUERY:
56                current_query = self._refine_query(query, context)
57
58            elif action == AgentAction.GENERATE:
59                return self._generate_answer(query, context)
60
61            elif action == AgentAction.STOP:
62                return "抱歉，我无法回答这个问题。"
63
64        return self._generate_answer(query, context)
65

74

82{context}
83

四、RAG关键组件详解

4.1 文档分块策略

分块是RAG效果的基础，不当的分块会严重损害检索质量。

策略优点缺点适用场景
固定长度简单语义截断通用场景
句子级语义完整块过小短文本
段落级语义连贯块过大长文档
语义分块最优质量计算成本高高质量需求
递归分块灵活需调参生产环境

 5def recursive_chunk(text: str, chunk_size: int = 500, chunk_overlap: int = 50,
 6                    separators: list[str] = None) -> list[str]:
 7    if separators is None:
 8        separators = ["\n\n", "\n", "。", "！", "？", ".", " "]
 9
10    if len(text) <= chunk_size:
11        return [text]
12
13    separator = separators[0]
14    remaining_separators = separators[1:]
15
16    if separator in text:
17        splits = text.split(separator)
18    else:
19        if remaining_separators:
20            return recursive_chunk(text, chunk_size, chunk_overlap, remaining_separators)
21        splits = [text[i:i + chunk_size] for i in range(0, len(text), chunk_size - chunk_overlap)]
22
23    chunks = []
24    current_chunk = ""
25
26    for split in splits:
27        if len(current_chunk) + len(split) > chunk_size and current_chunk:
28            chunks.append(current_chunk.strip())
29            overlap_text = current_chunk[-chunk_overlap:] if chunk_overlap > 0 else ""
30            current_chunk = overlap_text + split + separator
31        else:
32            current_chunk += split + separator
33
34    if current_chunk.strip():
35        chunks.append(current_chunk.strip())
36
37    return chunks

4.2 上下文窗口管理

大模型的上下文窗口有限，需要合理管理检索结果的数量和长度。

 1def manage_context(
 2    retrieved_docs: list[tuple[str, float]],
 3    max_tokens: int = 4000,
 4    tokenizer=None
 5) -> str:
 6    context_parts = []
 7    current_tokens = 0
 8
 9    for doc, score in retrieved_docs:
10        doc_tokens = len(tokenizer.encode(doc)) if tokenizer else len(doc) // 2
11
12        if current_tokens + doc_tokens > max_tokens:
13            remaining = max_tokens - current_tokens
14            if remaining > 100:
15                truncated = doc[:remaining * 2]
16                context_parts.append(f"[相似度:{score:.3f}] {truncated}...")
17            break
18
19        context_parts.append(f"[相似度:{score:.3f}] {doc}")
20        current_tokens += doc_tokens
21
22    return "\n\n".join(context_parts)

4.3 评估指标

RAG系统需要从检索质量和生成质量两个维度评估。

指标含义计算方式
Recall@K前K个结果中相关文档的召回率相关文档数 / 总相关文档数
Precision@K前K个结果中相关文档的精确率相关文档数 / K
MRR首个相关文档排名的倒数1 / 首个相关文档排名
Faithfulness生成答案与检索上下文的一致性LLM评估
Relevancy生成答案与用户问题的相关性LLM评估

总结

本章系统讲解了RAG技术的原理与演进：

  1. Naive RAG：基础的三阶段架构（索引-检索-生成），适合简单场景
  2. Advanced RAG：在检索前中后三个环节优化，显著提升检索质量
  3. GraphRAG：结合知识图谱，解决全局性问题的推理需求
  4. Agentic RAG：引入Agent自主决策，实现自适应检索和多步推理
  5. 关键组件：分块策略、上下文管理、评估指标是RAG效果调优的核心

RAG不是一成不变的技术，而是根据场景需求不断演进的架构。下一章将进入RAG实战，通过完整项目将理论落地。
