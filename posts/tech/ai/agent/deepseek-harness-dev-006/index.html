概述

从本篇开始进入实战。目标是做出一个真正能每天用的插件：kb-lite——本地 Markdown/文本知识库检索。对标社区热门插件 ICCuse/dsh-knowledge（kb_add/kb_search）、imkelt/DSH-RAG、Breeze136/dsh-kb-rag，但做到零外部依赖：不装向量模型、不起外部服务、不需要 API Key，配好 overlay 就能跑。

应用场景：把团队文档、会议纪要、API 手册、个人笔记丢进一个目录，之后让 Agent「先查知识库再回答」，答案带出处。

一、需求与设计

1.1 能力清单

工具行为对标社区插件
kb_add读文件（或直接传文本）→ 切块 → 建倒排索引dsh-knowledge 的 kb_add
kb_searchBM25 检索 → 带出处片段列表dsh-knowledge 的 kb_search
kb_list列出已入库文档DSH-RAG 的库管理
kb_stats文档数/块数/词项数dsh-kb-sieve 的统计

1.2 技术选型与取舍

决策点选择理由
检索算法BM25（纯内存计算）零依赖、可解释、短文档检索质量足够
分词拉丁词 + 中文二元组（bigram）不依赖分词词典，中英混合文本都能覆盖
持久化单文件 JSON + 原子写无数据库依赖；千级文档规模完全够用
向量检索不做（留作扩展）引入 embedding 模型会破坏「零依赖可复现」；第九节给出混合方案

什么时候该换 SQLite FTS5 / 向量库：文档数过万、或需要语义泛化检索时。对个人与小团队知识库，BM25 + JSON 是性价比最高的起点——先跑起来，再按需升级。

三、分词与切块

3.1 分词：拉丁词 + 中文二元组

中文检索没有分词器也能做：把连续中文切成二元组（bigram）。查询「学习」含 term 学习，库中含「深度学习」的块有 深度、度学、学习，精确匹配即可命中。bigram 方案无需词典、无 OOV，是中文零依赖检索的经典做法。

 1const CJK = /[\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff]/
 2const LATIN = /[a-z0-9][a-z0-9_.+-]*/g
 3
 4export function tokenize(text: string): string[] {
 5  const tokens: string[] = []
 6  const lower = text.toLowerCase()
 7  // 1) 拉丁词与数字整词保留
 8  for (const m of lower.matchAll(LATIN)) tokens.push(m[0])
 9  // 2) 连续 CJK 段取二元组
10  let run = ''
11  const flush = () => {
12    if (!run) return
13    if (run.length === 1) {
14      tokens.push(run)
15    } else {
16      for (let i = 0; i + 1 < run.length; i++) tokens.push(run.slice(i, i + 2))
17    }
18    run = ''
19  }
20  for (const ch of lower) {
21    if (CJK.test(ch)) run += ch
22    else flush()
23  }
24  flush()
25  return tokens
26}

3.2 切块：段落聚合 + 重叠

切块策略直接影响检索质量：按空行分段，向块里贪心聚合，超过 chunkSize 就切；相邻块保留 chunkOverlap 字符重叠，避免答案正好跨块被切断。超长段落（如一整页日志）硬切。

 1export function chunkText(text: string, size: number, overlap: number): string[] {
 2  const paras = text.replace(/\r\n/g, '\n').split(/\n{2,}/)
 3  const chunks: string[] = []
 4  let buf = ''
 5  for (const p of paras) {
 6    if (buf && buf.length + p.length + 2 > size) {
 7      chunks.push(buf)
 8      buf = buf.slice(Math.max(0, buf.length - overlap)) + '\n\n' + p
 9    } else {
10      buf = buf ? `${buf}\n\n${p}` : p
11    }
12  }
13  if (buf.trim()) chunks.push(buf)
14  // 超长块硬切
15  const out: string[] = []
16  const step = Math.max(50, size - overlap)
17  for (const c of chunks) {
18    if (c.length <= Math.floor(size * 1.5)) {
19      out.push(c)
20    } else {
21      for (let i = 0; i < c.length; i += step) out.push(c.slice(i, i + size))
22    }
23  }
24  return out
25}

四、BM25 检索器

索引结构：每块存 tf（词频）与 len（块长）；全局存 df（文档频率）与 avgLen（平均块长）。BM25 打分：

score(q, d) = Σ_{t∈q} IDF(t) · f(t,d)·(k1+1) / ( f(t,d) + k1·(1 − b + b·|d|/avgdl) )
IDF(t)      = ln( 1 + (N − n(t) + 0.5) / (n(t) + 0.5) )

k1=1.5（词频饱和）、b=0.75（长度惩罚）。返回前把分数归一化到 0~1（除以最高分），方便模型判断相关性强弱。

 1const K1 = 1.5
 2const B = 0.75
 3
 4export class KnowledgeBase {
 5  constructor(private data: KBData) {}
 6
 7  static empty(): KnowledgeBase {
 8    return new KnowledgeBase({ version: 1, docs: [], chunks: [], df: {}, avgLen: 0 })
 9  }
10
11  toJSON(): KBData {
12    return this.data
13  }
14
15  add(title: string, source: string, text: string, chunkSize: number, chunkOverlap: number) {
16    const pieces = chunkText(text, chunkSize, chunkOverlap)
17    const docId = `doc_${Date.now().toString(36)}${Math.random().toString(36).slice(2, 6)}`
18    this.data.docs.push({
19      id: docId,
20      title,
21      source,
22      addedAt: new Date().toISOString(),
23      chunkCount: pieces.length,
24    })
25    for (const piece of pieces) {
26      const tf: Record<string, number> = {}
27      for (const t of tokenize(piece)) tf[t] = (tf[t] ?? 0) + 1
28      for (const t of Object.keys(tf)) this.data.df[t] = (this.data.df[t] ?? 0) + 1
29      const len = Object.values(tf).reduce((a, b) => a + b, 0)
30      this.data.chunks.push({ docId, text: piece, tf, len })
31    }
32    const total = this.data.chunks.reduce((a, c) => a + c.len, 0)
33    this.data.avgLen = this.data.chunks.length ? total / this.data.chunks.length : 0
34    return { docId, chunkCount: pieces.length }
35  }
36
37  search(query: string, topK: number, source?: string) {
38    const N = this.data.chunks.length
39    const qTokens = tokenize(query)
40    const scored: { chunk: Chunk; score: number }[] = []
41    for (const chunk of this.data.chunks) {
42      if (source) {
43        const doc = this.data.docs.find((d) => d.id === chunk.docId)
44        if (doc && doc.title !== source && doc.source !== source) continue
45      }
46      let score = 0
47      for (const t of qTokens) {
48        const f = chunk.tf[t]
49        if (!f) continue
50        const n = this.data.df[t] ?? 0
51        const idf = Math.log(1 + (N - n + 0.5) / (n + 0.5))
52        const denom = f + K1 * (1 - B + (B * chunk.len) / (this.data.avgLen || 1))
53        score += (idf * (f * (K1 + 1))) / denom
54      }
55      if (score > 0) scored.push({ chunk, score })
56    }
57    scored.sort((a, b) => b.score - a.score)
58    const top = scored.slice(0, Math.max(1, topK))
59    const max = top.length ? top[0].score : 1
60    return top.map(({ chunk, score }) => {
61      const doc = this.data.docs.find((d) => d.id === chunk.docId)!
62      return {
63        docId: chunk.docId,
64        title: doc.title,
65        source: doc.source,
66        score: Number((score / max).toFixed(4)),
67        snippet: chunk.text.length > 200 ? `${chunk.text.slice(0, 200)}…` : chunk.text,
68      }
69    })
70  }
71
72  list() {
73    return this.data.docs.map((d) => ({ ...d }))
74  }
75
76  stats() {
77    return {
78      docs: this.data.docs.length,
79      chunks: this.data.chunks.length,
80      terms: Object.keys(this.data.df).length,
81      avgChunkLen: Math.round(this.data.avgLen),
82    }
83  }
84}

5.1 设计要点回顾

  • 懒加载 + 单飞：ready() 保证首次读盘只发生一次，并发工具调用不打架；
  • 写后即持久化：每次 kb_add 落盘，插件卸载不丢数据——所以不需要 ctx.effect 做 flush；
  • 领域结果不抛异常：内容为空返回 { added: false, reason }；文件不存在（基础设施故障）才抛；
  • signal 传导：读文件传 exec.signal；
  • 卡片意图：kb_search 声明 search 卡片并带截断标记。

八、与社区插件的对照

插件核心能力与 kb-lite 的差异
ICCuse/dsh-knowledgekb_add/kb_search/kb_show/kb_timeline，与 Codex CLI 共享格式格式互通；kb-lite 专注「最小可跑」
imkelt/DSH-RAG多目录增量索引、BM25+向量混合检索、可定位来源向量混合是下一步扩展（见下节）
Breeze136/dsh-kb-rag10 个工具、本地 bge 嵌入 + SQLite重量级方案；千篇文档 86s 入库
omdsh-dev/dsh-kb-sieveSQLite FTS5、可审计知识库包存储层换 SQLite 即可对标

结论：kb-lite 覆盖了日常检索的大部分需求，全部代码约 400 行，是继续演进的完美基线。

九、扩展方向（按优先级）

  1. 混合检索：kb_search 增加可选 embedding 召回（本地 bge 或 OpenAI 兼容 API），用 RRF 融合 BM25 与向量分数——对标 imkelt/DSH-RAG；
  2. 增量索引：入库前比对文件 mtime/内容 hash，跳过未变化文档，支持「同步整个目录」；
  3. 目录监听：在 ctx.effect() 里用 fs.watch 监听文档目录，变更自动重建索引，插件卸载时 close() watcher（第 004 篇的 effect 用武之地）；
  4. 引用回跳：卡片里带 locations 让编辑器跳转到源文件行；
  5. 多库隔离：用服务隔离（group）给不同项目配不同索引目录，见第 008 篇。

十、练习

  1. 给 kb_add 加 tags 参数，入库时写入 DocMeta，kb_search 支持按 tag 过滤；
  2. 实现 kb_remove(docId)：从 docs/chunks/df/avgLen 中完整移除一个文档（注意 df 与 avgLen 的重算）；
  3. 把 kb_search 的 topK 默认值改为从 ctx.get() 取一个可选服务（模拟「用户偏好服务」），练习可选依赖；
  4. （进阶）把存储层换成 node:sqlite 的 FTS5，比较查询延迟。

小结

  • 一个可用插件 = 好配置 + 清晰索引模型 + 守契约的工具；
  • 零依赖中文检索三件套：bigram 分词、段落切块+重叠、BM25；
  • 懒加载+单飞、写后即持久化、原子写，是本地存储插件的标准套路；
  • 领域结果进规范值，基础设施故障才抛异常；
  • 下一篇实战二：跨会话记忆插件——把事件系统与被动捕获用起来。
